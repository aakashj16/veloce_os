## Architecture implications

1. **Do not assert that native Zoom needs Xorg in every Linux configuration.** This physical KDE Plasma/Wayland run successfully shared individual windows using the desktop's system window-capture picker. Documentation/vendor behavior and portal/compositor/app-version details may differ; test exact combinations.
2. **Retain LXQt/Xorg/Openbox as Veloce's provisional Stage 1/2 baseline** until the Veloce browser/meeting, hardware, performance and protected-Notes matrices are satisfied. KDE/Wayland success is useful comparative evidence, not evidence that LXQt/Labwc or LXQt/Wayfire passes.
3. Keep applications on demand and avoid unnecessary background services. Never disable firewall, networking, audio, power management or notifications simply to satisfy memory targets.
4. Do not transfer the ARIA idle figure directly to either Veloce performance mode. Standard remains **≤1,024 MiB**; Enhanced remains **≤2,048 MiB** on the defined five-sample protocol, with all normal services enabled.
5. Do not mark protected **Notes** capture exclusion as passed. Working window/display capture does not imply a guaranteed private overlay.
6. Do not claim Veloce is installed or that a release ISO exists. ARIA is a stock Debian workstation used to discover compatibility and operational lessons.

- Capture five idle memory samples at prescribed intervals with system services enabled and record CPU/GPU/battery data; repeat on Wayland candidate sessions when available.
- Run the [meeting matrix](../compatibility.md#meeting-tests) on each Veloce-supported compositor and browser, plus protected Notes capture-exclusion tests when the feature is implemented.
- Preserve privacy: do not publish hostname, username, disk UUIDs, serials, addresses, SSIDs, credentials or personal meeting screenshots.
